## 0. 要解决的问题

用户实测后提出四点：

1. **先认软件，再转语法。** 规则和配置模板都应该先确定用户用的是什么软件，系统按该软件的语法自动转换。用户不需要知道"内核""格式""YAML/LIST"。
2. **软件要有图标。** 目前到处是纯文字（"Mihomo 系列 · YAML""iOS 系列 · LIST"），小白认不出自己的软件。
3. **配置模板要足够引导。** 一屏只问一个问题，每一步都说明"为什么问"和"推荐选什么"。
4. **机场订阅可能有多条。** 现在向导只能填一条。

核心原则不变：**围绕小白，一步一步带着走**。

## 1. 软件分类（语法族）

用户界面只出现"软件名 + 图标 + 平台"。语法族是系统内部用来决定输出格式的，不展示给用户。

### 1.1 三个语法族

| 语法族（内部） | 代表软件 | 规则订阅输出 | 完整配置输出 |
| --- | --- | --- | --- |
| **Clash / mihomo 系** | Clash Verge Rev、FlClash、Clash Party（Mihomo Party）、Clash Meta for Android、ClashMi、OpenClash（路由器）、**Stash** | YAML rule-provider（classical / domain / ipcidr） | mihomo 配置；Stash 用 Stash 方言 |
| **sing-box 系** | sing-box 官方客户端（SFA / SFI / SFM）、Karing、Hiddify 等 | sing-box rule-set（JSON source） | sing-box 配置（1.12 语法） |
| **苹果原生系（Surge 类语法）** | Surge、Loon、Quantumult X、Shadowrocket、**Egern**；另有安卓上的 Surfboard（Surge 语法） | LIST（每个软件细节不同，如 QX 用 HOST 写法、Loon / QX 省略 PROCESS-NAME） | 各自配置文件（Egern、Surfboard 完整配置原计划 1.2.0） |

> **需要你确认的一处分类**：你提到"基于 sing-box 内核的软件（三端都有 egern，stash）"。按我核对的资料：**Stash 使用 Clash 兼容语法**（配置与 mihomo 基本一致，只有少量 Stash 扩展），**Egern 使用自己的 YAML 配置**，概念上更接近 Surge。两者都只有 iOS / iPadOS / macOS 版本。所以本文把 Stash 归入 Clash / mihomo 系，Egern 归入苹果原生系。如果你的意思是"按平台分三端"，或者你实测这两个软件可以直接吃 sing-box 配置，请指出，我按你的分类改。**【待定 D1】**

| 字段 | 说明 | 例：Clash Verge Rev |
| --- | --- | --- |
| `id` | 软件标识 | `clash-verge-rev` |
| `name` / `aliases` | 显示名与别名（搜索用） | Clash Verge Rev / Clash Verge |
| `platforms` | 平台 | Windows、macOS、Linux |
| `family` | 语法族（内部） | `mihomo` |
| `ruleOutput` | 规则订阅用哪种文件 | `mihomo` YAML |

## 2. 软件图标

### 2.1 方案

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| **A（推荐）** | 使用各软件官方图标，内置 64×64 / 128×128 webp，在 THIRD-PARTY-NOTICES 写明"图标版权归各软件所有，仅用于识别" | 小白一眼认出 | 闭源软件（Surge、Loon、QX、Shadowrocket、Stash、Egern）的图标受版权保护，属于指示性使用，开源项目里常见，但不是零风险 |
| B | 自绘统一风格的简化图标（首字母 + 品牌色） | 无版权问题，风格统一 | 认不出来，违背"图标"的初衷 |
| C | 开源软件用官方图标（Clash Verge Rev、FlClash、sing-box、Karing 等，按各自许可证），闭源软件用 B | 折中 | 风格不统一 |

**图标来源**：我不会自行从应用商店下载。A 或 C 需要你提供图标文件，或授权我从各开源项目仓库按许可证取用。所有图标缺失时退回 B 的首字母徽章，保证界面不出现空白。**【待定 D3】**

## 3. 统一的"选择你的软件"组件

规则侧和模板侧共用一个组件 `AppPicker`。

```
┌ 你用的是哪个软件？ ─────────────────────────────┐
│ [iPhone/iPad] [Mac] [Windows] [安卓] [路由器]    │  ← 先选平台（记住上次选择）
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐                    │
│ │图标│ │图标│ │图标│ │图标│                    │
│ │小火箭│ │圈X │ │Loon│ │Surge│                  │
│ └────┘ └────┘ └────┘ └────┘                    │
│ 🔍 搜索软件名                                    │
│ 不知道自己用的是哪个？ → 打开手机/电脑上的代理软件，  │
│   对照图标找一找；还没有装软件 → 推荐清单           │
└────────────────────────────────────────────────┘
```

- 规则侧单选，模板侧可多选（"我手机和电脑都要用"）。
- 选择记在本机（localStorage），下次直接进入该软件。
- "还没有装软件"给出每个平台 1–2 个推荐，只放名称与官方地址文字，不放下载链接按钮。
- 不显示语法族、内核、格式等字样。

## 4. 分流规则侧改造

### 4.1 订阅页（取代"按格式分组"）

现在：规则详情 → 按"Mihomo 系列 · YAML / iOS 系列 · LIST / sing-box 系列 · JSON / 纯文本"展开一堆链接。
改为：

```
┌ AI 订阅 ───────────────────────────────────────┐
│ 访问方式：[私密（带密钥）▾]                       │
│ 你的软件：[图标 Clash Verge Rev ▾]  ← AppPicker   │
│ ─────────────────────────────────────────────── │
│ 订阅链接   https://…/AI.yaml        [复制]        │
│ 在 Clash Verge Rev 里这样用：                     │
│   ① 打开「订阅」…  ② …  ③ …                       │
│ ▸ 我会自己写配置：查看引用片段（已有）              │
│ ▸ 其他格式（高级）：列出全部链接                    │
└────────────────────────────────────────────────┘
```

- 一个软件只给一个最合适的链接（例如 mihomo 系默认 classical YAML，ipcidr / domain 只在"其他格式"里）。
- 原来的全部链接收进"其他格式（高级）"，老用户仍能找到。
- 订阅中心首页（规则卡片列表）顶部增加"你的软件"，选定后点规则直接复制该软件的链接。

### 4.2 规则构建

规则构建本身与软件无关（同一份规则输出到所有软件），保持现状。只在添加规则时，若该类型在用户已选软件上不生效，给出提示，例如"程序名规则在小火箭、圈X、Loon 上不生效"。

## 5. 配置模板侧改造：一步一问的引导向导

### 5.1 原则

- 一屏一个问题，标题用问句，副标题说明"为什么问"。
- 每题都有"推荐"项并默认选中，可以一路点"下一步"。
- 顶部进度条显示"第 N 步 / 共 6 步"，可以返回，已填内容保留。
- 界面不出现：模板、内核、语法、策略组、槽位、组件、发布等词。页面标题用"生成配置""我的配置"。**【待定 D4：导航里的"配置模板"是否改名为"我的配置"】**

### 5.2 步骤

| 步骤 | 问题 | 内容 | 默认 |
| --- | --- | --- | --- |
| 1 | **你在哪些软件上用？** | AppPicker 多选，按平台分组，带图标 | 无，至少选一个 |
| 2 | **你的机场订阅是什么？** | 订阅列表，可以添加多条（见第 6 节）；每条可命名，填完自动检查并显示"识别到 86 个节点：香港 20 · 日本 15…"；可以跳过 | "机场 1" |
| 3 | **哪些网站要单独处理？** | 场景卡片（带图标）：国内直连、广告拦截、AI、Telegram、流媒体…；顶部"推荐组合 / 少一点 / 全都要"三个快捷选项（取代"极简 / 轻量 / 标准 / 重度"） | 推荐组合 |
| 4 | **要不要用你自己整理的规则？** | 列出规则模块里的规则，勾选并选"走代理 / 直连 / 拦截"；没有规则时说明可以跳过 | 不勾选 |
| 5 | **节点怎么挑？** | 自动选最快（推荐）/ 我自己手动选 / 按地区分组；有多个机场时增加"按机场分组" | 自动选最快 |
| 6 | **给这份配置起个名字** | 名称 + 一屏摘要（软件、机场、场景），可点任意一项回去修改 | "我的配置" |

**完成页**：每个软件一张"导入卡"：图标、一键导入（已核实时）、复制链接、二维码（待 D6）、2–3 步图文"导入后怎么用"。苹果原生系软件（节点由软件自己管理）额外显示"还需要在软件里添加机场订阅"的步骤，并列出每个机场的名称（不显示地址）。

### 5.3 模板详情

保留"分流 / 节点 / 输出"三个标签与"高级编辑"开关。"输出"改为软件卡片（带图标），"节点"支持多机场（第 6 节）。

## 6. 多条机场订阅

### 6.1 现状

后端数据模型已经支持多个节点来源（模板 `slots[]`、按 `(publication_id, slot_id)` 加密存储），七个编译器都会遍历全部来源。只有向导（快速创建）和普通视图写死了 `slot-main`。所以本项主要是向导、普通视图与接口的改造，不需要改表结构。

### 6.2 用户界面

```
┌ 你的机场订阅 ───────────────────────────────────┐
│ ① 机场 1  ·  已填写（无法查看原文）  86 个节点 [更换][删除]│
│ ② 备用机场 ·  已填写                 31 个节点 [更换][删除]│
│ [+ 再添加一个机场]（最多 10 个）                    │
│ 🔒 订阅地址加密保存，之后任何人都看不到原文          │
└────────────────────────────────────────────────┘
```

- 每条订阅可命名（默认"机场 1""机场 2"），名称会出现在分组名里，例如"机场 1 · 香港"。
- 单条订阅失败不影响其他订阅，显示该条的白话错误。

### 6.3 节点怎么组合

| 选项 | 说明 |
| --- | --- |
| **合并所有机场（推荐）** | 所有机场的节点放在一起，"自动选最快 / 按地区"跨机场生效 |
| **每个机场一个分组** | 每个机场单独一组，外加"全部节点"组；适合主力 + 备用 |

### 6.4 各语法族的处理

| 语法族 | 节点接入 | 多机场做法 |
| --- | --- | --- |
| Clash / mihomo 系、Stash、Surge | A：配置里引用订阅，软件自己拉取 | 每个机场一个 proxy-provider（Surge 用 policy-path）；地区组与"全部节点"组按筛选器跨 provider 引用 |
| sing-box 系 | B：服务端拉取并嵌入节点 | 分别拉取、分别缓存（现有 30 分钟加密快照）；节点名加机场名前缀避免重名；单个机场失败时用它上次成功的快照 |
| 圈X、Loon、小火箭 | C：节点由软件自己管理 | 配置只按名称筛选节点；完成页逐个列出"在软件里添加这些订阅"的步骤。Loon / 圈X 支持在配置里写远程订阅（`[Remote Proxy]` / `[server_remote]`），可以作为可选项，但这会让订阅地址出现在下发的配置文件中（与 A 类相同，受订阅链接的私密访问保护）。**【待定 D5】** |

### 6.5 后端改动

- `quick-create` 与普通视图接口接受订阅数组（名称 + 地址），每条生成一个节点来源并加密绑定到每个发布。
- 普通视图"节点"标签：列表增删、改名、更换（只写）、单条检查。
- 已有模板的 `slot-main` 在普通视图中显示为"机场 1"，无迁移。
- 节点预览接口支持一次检查多条，逐条返回结果；每次请求最多 10 条，仍走现有 SSRF 防护与限流。

## 6A. 配置模板本身的质量：参考 mihomo_yamls 的分析

用户指出：模板不能只是"能通过检查"，配置本身要好用。下面分析社区合集 [HenryChiao/mihomo_yamls](https://github.com/HenryChiao/mihomo_yamls)（2026-11-25 版本，约 40 位作者的 93 份 mihomo 配置，成功解析 90 份），先定 mihomo 的参考设计，再推广到其他软件。

> **许可证**：该仓库是 **AGPL-3.0**，本项目是 MIT。我们只能学习其结构与设计思路，**不能把其中的 YAML 复制进内置模板**，否则需要承担 AGPL 义务。用户自己通过"导入配置"导入社区模板（地址由用户填写，运行时获取）不受影响。

### 6A.1 社区配置的共性（90 份统计）

| 方面 | 统计 | 说明 |
| --- | --- | --- |
| 机场接入 | 84 份用 `proxy-providers` 引用订阅；**38 份同时接了多个机场** | 多机场是常态。常见写法：每个机场一个 provider，用 `override.additional-prefix` 给节点名加前缀（如"[优] ""[备] "）区分主力与备用 |
| 垃圾节点过滤 | provider 级 `filter` / `exclude-filter` 63 处 | 去掉"剩余流量""官网""到期"等信息节点 |
| 地区分组 | 1,381 个组用 `filter` 正则，1,244 个组用 `include-all` | 按名称正则动态收集节点，而不是逐个列出 |
| 组类型 | select 3,178、url-test 584、fallback 487、load-balance 186、smart 106 | `smart` 是第三方分支内核才有，官方 mihomo 不支持，不跟进 |
| 组图标 | 4,541 个组里 **3,521 个带 `icon`** | Clash Verge Rev、FlClash、Stash 等会显示组图标，小白靠图标认组 |
| 隐藏辅助组 | 926 个组 `hidden: true` | 把"香港自动""均衡"等辅助组藏起来，界面只留用户需要点的组 |
| 测速参数 | `lazy`、`timeout`、`max-failed-times`、`expected-status` 各约 2,000 处 | 减少无用测速、失败快速切换 |
| 规则来源 | `RULE-SET` 约 3,900 条，`GEOSITE/GEOIP` 约 990 条；rule-provider 格式 yaml 1,924、**mrs 1,746**、text 310 | 大量使用 mrs 二进制规则集，加载快、体积小 |
| DNS | fake-ip 72 份；`proxy-server-nameserver` 57；`nameserver-policy` 44；`respect-rules` 42 | 国内域名走国内 DNS，代理节点域名单独解析，DNS 跟随分流 |
| 嗅探 / TUN | sniffer 71 份；tun 段 62 份 | 嗅探提升分流准确度；TUN 由图形客户端开关控制 |
| 规模 | 中位数 **35 个组**、42 条规则（范围 1–177 组） | 面向熟手；对小白来说组太多 |
| 常见组名 | 自动选择、故障转移、手动选择、Telegram、Google、YouTube、AI、Apple、Microsoft、漏网之鱼、全部节点、香港自动… | 命名习惯高度一致，可作为我们的默认命名 |

一个典型的成熟写法（HenryChiao/MihomoAIO，结构概括，非原文）：先用 YAML 锚点定义"机场基础参数""各类组基础参数""各地区过滤正则"；机场分主力、备用两个 provider 并加前缀；每个服务组都是"默认项在前 + 全部地区策略 + 直连"的 select；地区策略组下挂自动 / 均衡子组并隐藏。

### 6A.2 我们当前输出（标准模板 / mihomo）的对比

| 方面 | 现状 | 差距 |
| --- | --- | --- |
| 机场接入与过滤 | provider 引用 + `exclude-filter` 过滤信息节点 + 健康检查 | 已具备；**只支持一个机场**，无前缀 |
| 地区分组 | url-test + `use` + 精确地区正则（比社区更严谨，排除了"日期""新节点"等误伤） | 已具备；未隐藏辅助组 |
| 组图标 | 无 | **缺** |
| 规则来源 | `GEOSITE` / `GEOIP`（依赖 GeoSite.dat / GeoIP.dat） | 首次启动要下载大文件，小白容易卡在"规则加载失败"；应优先 rule-set（mrs 计划在 1.2.0） |
| DNS | fake-ip + 国内 DoH + `fallback` | 缺 `nameserver-policy`（国内域名定向）、`proxy-server-nameserver`、`respect-rules`；`fallback` 是旧写法 |
| 嗅探 | 无 | **缺** sniffer |
| TUN | 无 tun 段 | 图形客户端可自己开启，可接受；可选写入默认关闭的 tun 段 |
| 测速参数 | interval、tolerance | 缺 `lazy`、`timeout`、`expected-status` |
| 组数量 | 标准模板约 26 个组 | 对小白偏多，且全部可见 |

### 6A.3 mihomo 参考设计（小白版）

目标：**导入即用、界面清爽、出问题能自愈**。

| 层 | 设计 |
| --- | --- |
| 机场 | 每个机场一个 provider，节点名加"机场名 · "前缀；统一信息节点过滤；健康检查 + `lazy` |
| 可见的组（小白只看到这些，约 8–12 个） | 🚀 节点选择（自动选择 / 各地区 / 各机场 / 直连）· ⚡ 自动选择 · 用户勾选的场景组（AI、Telegram、流媒体…，每个都是"推荐项在前"的 select）· 🐟 漏网之鱼 |
| 隐藏的组 | 地区自动组、各机场组、故障转移组：`hidden: true`，只作为可见组的选项 |
| 图标 | 每个组都带图标；复用 1.0.x 已有的"图标包"设置（默认图标包 + 用户自定义图标包地址） |
| 规则 | 国内直连、广告、各服务优先用 rule-set（behavior 用 domain / ipcidr 提速）；1.2.0 起 mihomo 输出 mrs；只有用户选了"兼容老版本"才用 geodata |
| DNS | fake-ip；`nameserver-policy` 让国内域名走国内 DoH；`proxy-server-nameserver` 解析节点域名；`respect-rules: true`；去掉 `fallback` |
| 嗅探 | 默认开启 sniffer（HTTP / TLS / QUIC） |
| 运行参数 | `unified-delay`、`tcp-concurrent`、`find-process-mode: strict`、`profile.store-selected`；不写死端口、面板密码（图形客户端自己管理） |
| 档位 | 用目标命名而不是 ProMax / AIO：**推荐组合**（默认）、**少一点**（只分国内外 + AI）、**全都要**（全部场景 + 按地区） |

这些都是编译器层面的改动，模板中间结构基本够用：多机场、图标、隐藏、rule-set 来源都已有对应字段，或者只需小幅扩展。

### 6A.4 推广到其他软件

同一份模板中间结构，按软件能力编译。下表是各软件对应能力的写法，**全部需要按各软件官方文档逐项核实后再实现**：

| 能力 | mihomo / Stash | sing-box | Surge | Loon | Quantumult X | Shadowrocket | Egern |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 多机场接入 | 每个机场一个 `proxy-providers` | 服务端拉取后嵌入，节点名加前缀（官方版无 provider） | 每个机场一个 `policy-path` 外部策略 | `[Remote Proxy]` 或在软件里添加 | `[server_remote]` 或在软件里添加 | 在软件里添加订阅 | 软件内订阅（1.2.0） |
| 按地区筛节点 | `filter` 正则 | 服务端按正则分组 | `policy-regex-filter` | `NameRegex` | `server-tag-regex` | `policy-regex-filter` | 待核实 |
| 自动测速组 | url-test / fallback | urltest | url-test / fallback / smart | url-test / fallback | url-latency-benchmark / available | url-test / fallback | 待核实 |
| 组图标 | `icon` | 不支持 | 待核实 | `img-url` | `img-url` | 待核实 | 待核实 |
| 隐藏辅助组 | `hidden` | 不支持（可省略辅助组） | 待核实 | 待核实 | 待核实 | 待核实 | 待核实 |
| 规则集 | rule-provider（yaml / mrs） | rule_set（source / srs） | `RULE-SET` | `[Remote Rule]` | `[filter_remote]` | `RULE-SET` | 待核实 |
| DNS 分流 | `nameserver-policy` | dns.rules | `[Host]` + DNS 设置 | `[Host]` | `[dns]` | `[Host]` | 待核实 |
| 嗅探 | sniffer | route `sniff` 动作 | 自带 | 自带 | 自带 | 自带 | 待核实 |

做法：先把 mihomo 参考设计落地（6A.3），每推广一个软件就补齐该列的核实结果与编译器实现，并在真机清单（`docs/device-test-checklist.md`）里加对应用例。

### 6A.5 社区模板的位置

- 内置模板由我们自己按 6A.3 编写，不复制社区内容。
- "导入配置"保留：用户可以填社区模板地址作为起点（现有 mihomo YAML 导入能力）；界面只放在模板列表的次要入口，并提示"导入的配置由原作者维护，我们会自动套用你的机场和规则"。
- 是否在界面里列出推荐的社区模板链接（只放文字链接，不内置内容），见 D10。
