## 0. 目标

1. **先认软件，再转语法。** 用户只选"我用的是哪个软件"，系统按该软件的语法输出。
2. **配置按复杂度分三档。** 小白用简易版，进阶用户用进阶版，熟手用专业版；每一档都能一步步引导完成。
3. **把配置拆成看得懂的积木。** 节点池（节点从哪来、怎么分）→ 策略组（流量走哪个节点池）→ 模块组（DNS 防泄漏等附加能力），每块都有图标和一句话说明。
4. **多条机场订阅**是常态。
5. **全局动效**统一、连贯，覆盖页面切换在内的所有界面。

## 1. 核心概念

```
 机场订阅（1–10 条）
      │ 拉取节点
      ▼
 ┌──────────┐   按正则筛选、测速方式
 │  节点池   │  例：🇭🇰 香港节点、🇺🇸 美国节点、⚡ 全部节点、🏷 低倍率
 └────┬─────┘
      │ 被策略组引用（候选）
      ▼
 ┌──────────┐   按规则把流量分给节点池 / 直连 / 拦截
 │  策略组   │  例：🤖 AI 服务 → 优先 美国节点池；📺 流媒体 → 香港节点池
 └────┬─────┘
      │ 规则来源：内置规则目录 + 「分流规则」模块里用户自己的规则
      ▼
 ┌──────────┐   附加能力，可开关
 │  模块组   │  例：🛡 DNS 防泄漏、🚫 阻断加密 DNS、🎮 游戏下载直连
 └────┬─────┘
      ▼
 配置模板（以上组合 + 档位）──按软件编译──▶ 订阅链接
```

| 概念 | 小白看到的名字 | 现有代码基础 | 改动 |
| --- | --- | --- | --- |
| 节点来源 | 机场订阅 | 模板 `slots[]` | 多条（R3 进行中） |
| **节点池（新）** | 节点池 | 模板 `regionGroups`（地区 + 附加包含 / 排除正则） | 升级为通用节点池对象，见第 3 节 |
| **策略组（原"场景库"）** | 策略组 | 应用组件 `AppCard` | 改名、细分类、自动图标，见第 4 节 |
| **模块组（扩充）** | 模块 | 5 个增强模块（防 DNS 泄漏、阻断加密 DNS、IP 补 no-resolve、游戏下载直连、局域网与内网穿透直连） | 扩充并分组，见第 5 节 |
| 档位 | 简易 / 进阶 / 专业 | T1 的 少一点 / 推荐组合 / 全都要 | 改为按复杂度分档，见第 2 节 |

"策略组"是各客户端都用的叫法（proxy-groups、Policy Group），保留这个词，但第一次出现时配一句说明："策略组 = 一类网站走哪条线路"。

## 2. 三档复杂度

### 2.1 定义

| | **简易** | **进阶** | **专业** |
| --- | --- | --- | --- |
| 适合谁 | 只想能用的小白 | 想让不同网站走不同地区的用户 | 熟手、多机场、对稳定性有要求 |
| 节点池 | **不区分**：只有一个"全部节点"（含自动选最快） | **按地区**：香港、台湾、日本、新加坡、美国、韩国、其他；每池自动测速 | **细分**：地区池 + 按机场池 + 特征池（低倍率、家宽、专线、游戏等，正则匹配）+ 故障转移 / 负载均衡池 |
| 策略组 | **3 个**：🚀 代理（PROXY）、🎯 直连（DIRECT）、🚫 拦截（REJECT） | 基础组 + 用户勾选的常用策略组（AI、Telegram、流媒体…），每组候选为各地区节点池 | 细分到具体服务（OpenAI、Claude、Gemini 分开；Netflix、Disney+、哔哩哔哩港澳台分开…），每组可指定优先节点池与故障转移顺序 |
| 规则 | 国内 → 直连；广告 → 拦截；其余 → 代理；用户自己的规则按"代理 / 直连 / 拦截"三选一放到最前 | 每个策略组带自己的规则；国内直连、广告拦截照旧 | 同进阶，并可调整规则顺序、引用社区规则 |
| 模块组 | 只开默认安全项（DNS 防泄漏） | 默认安全项 + 常用项（局域网直连、嗅探） | 全部模块可选（第 5 节） |
| 客户端里看到的组 | 3 个 | 约 8–12 个（辅助池隐藏） | 不限，辅助池默认隐藏、可设为可见 |

### 2.2 与 T1 的关系

T1 已经实现了进阶档需要的大部分能力（地区池、隐藏辅助组、图标、DNS / 嗅探、mrs 规则集、多机场前缀）。T1 的三档名称（少一点 / 推荐组合 / 全都要）是**按场景多少**分的，本版改为**按复杂度**分：

- 简易 = 新增（最少的组，无地区池）
- 进阶 ≈ T1 的"推荐组合"
- 专业 ≈ T1 的"全都要" + 细分节点池 + 全部模块

场景多少（勾哪些策略组）改为在进阶 / 专业档内单独勾选，不再作为档位。旧档 slug 继续兼容映射。**【待定 D12】**

### 2.3 向导中的选择

```
┌ 你想要多精细？ ─────────────────────────────────┐
│ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │
│ │  🌱 简易     │ │  🌿 进阶     │ │  🌳 专业     │ │
│ │ 能用就行     │ │ 不同网站     │ │ 我想自己     │ │
│ │ 3 个分组     │ │ 走不同地区   │ │ 细调每一块   │ │
│ │ （推荐小白） │ │             │ │             │ │
│ └─────────────┘ └─────────────┘ └─────────────┘ │
│ 选完之后随时可以在模板里升级或降级                  │
└────────────────────────────────────────────────┘
```

默认选中哪一档见 **【待定 D13】**。升级 / 降级时保留用户已做的选择，降级时被隐藏的细节在"高级编辑"里仍可见。

## 3. 节点池（新增）

### 3.1 定义

节点池 = 从机场订阅里**按名称正则筛出一批节点**，并决定这批节点怎么选。

| 字段 | 说明 | 例 |
| --- | --- | --- |
| 名称、图标 | 图标按名称 / 地区自动匹配（第 4.3 节），可手动换 | 🇭🇰 香港节点 |
| 来源 | 全部机场，或指定机场 | 全部 |
| 包含正则 | 节点名匹配才进池 | 地区内置正则（T1 已有，比社区更严谨） |
| 排除正则 | 匹配则踢出 | 信息节点（剩余流量、官网等，全局默认排除） |
| 选择方式 | 自动选最快（url-test）/ 故障转移（fallback）/ 负载均衡（load-balance）/ 手动选（select） | 自动选最快 |
| 测速参数 | 地址、间隔、容差、超时，默认值来自 T1 | 默认 |
| 在客户端中可见 | 默认隐藏（只作为策略组的候选） | 隐藏 |

### 3.2 节点池库（内置预设）

| 类别 | 预设 | 档位 |
| --- | --- | --- |
| 全部 | ⚡ 全部节点（自动选最快）、🖐 全部节点（手动选） | 全部 |
| 地区 | 香港、台湾、日本、新加坡、美国、韩国、英国、德国、其他地区…（沿用 T1 的 12 个地区正则） | 进阶起 |
| 机场 | 每个机场一个池（按来源，不靠正则） | 专业 |
| 特征 | 🏷 低倍率（如"0.5x""0.1倍"）、🏠 家宽 / 原生、🚄 专线（IPLC / IEPL）、🎮 游戏 | 专业 |
| 稳定性 | 🔁 故障转移（多个池按顺序兜底）、⚖ 负载均衡 | 专业 |

特征池的正则由我们自己整理并写测试样例，不复制社区内容。

### 3.3 编辑与预览

- 新建 / 编辑节点池时，右侧实时显示"会进入这个池的节点"（用已有的加密节点快照，不主动拉取机场）。
- 正则对小白隐藏：进阶档只能从预设里选；专业档可以编辑正则，并有"测试正则"输入框。
- 空池保护：某个池一个节点都没匹配到时，编辑页给出提示；编译时空池自动退化为直接引用"全部节点"，避免客户端报错。

### 3.4 各客户端怎么输出

| 客户端 | 节点池写法 |
| --- | --- |
| mihomo / Stash | 策略组 + `use` 引用 provider + `filter` / `exclude-filter` 正则（T1 已有） |
| sing-box | 服务端按正则筛出节点后写入 selector / urltest |
| Surge | `policy-path` + `policy-regex-filter` |
| Loon | `[Remote Filter]` 的 `NameRegex` |
| Quantumult X | `server-tag-regex` |
| Shadowrocket | `policy-regex-filter` |

写法均需按官方文档逐项核实（沿用 r1 §6A.4 的核实流程）。

## 4. 策略组（原"场景库"）

### 4.1 改名

- 界面中"场景库"改为"**策略组**"，"场景"统称"策略组"。路由 `/templates/scenes` 改为 `/templates/groups`，旧路由重定向；后端 `cards` API 保持不变，只改前端名称。
- 向导里仍用问句引导（"哪些网站要单独处理？"），列出的每一项就是一个策略组。

### 4.2 详细分类

| 分类 | 策略组示例 |
| --- | --- |
| 🧭 基础 | 节点选择、自动选择、漏网之鱼、直连、拦截 |
| 🤖 AI | OpenAI / ChatGPT、Claude、Gemini、Copilot、其他 AI |
| 💬 社交通讯 | Telegram、X / Twitter、Discord、WhatsApp、Line、Instagram / Facebook |
| 🎬 国际流媒体 | YouTube、Netflix、Disney+、HBO Max、Prime Video、TikTok |
| 📺 港澳台流媒体 | 哔哩哔哩港澳台、巴哈姆特、TVB |
| 🎵 音乐 | Spotify、Apple Music、YouTube Music |
| 🎮 游戏 | Steam、Epic、PlayStation、Xbox、Nintendo、游戏下载 |
| 🛠 开发者 | GitHub、GitLab、Docker Hub、npm / PyPI |
| ☁️ 云与办公 | Google、Microsoft、OneDrive、Dropbox、Notion |
| 🍎 Apple | Apple 服务、iCloud、App Store、Apple 推送 |
| 💳 金融支付 | PayPal、Stripe、海外银行 |
| 🛒 购物 | Amazon、eBay |
| 🛡 隐私与广告 | 广告拦截、隐私跟踪拦截 |
| 🏠 国内 | 国内直连、局域网直连、国内 CDN |
| ⏱ 其他 | 测速、BT / PT、加密货币 |

分类沿用现有组件的 `category` 字段，扩充取值；每个内置策略组都带规则来源（内置规则目录 / GeoSite / 社区规则地址）与推荐候选节点池（如 AI 推荐美国池）。具体收录名单我在实现前列出完整清单给你确认。**【待定 D14】**

### 4.3 图标自动匹配

- 匹配顺序：策略组名称里的 emoji → 服务名（OpenAI、Netflix…）→ 分类 → 地区（节点池）→ 角色（代理 / 直连 / 拦截 / 自动）→ 兜底图标。现有 `src/domain/templates/icons.ts` 已实现这条链，扩充服务词表即可。
- 图标来源：设置里的图标包（默认 Qure，1.0.x 起就是默认值）；用户可在策略组 / 节点池编辑里手动换图标。
- 界面里同一个图标既显示在我们的编辑器中，也写进客户端配置（支持图标的客户端会显示）。

## 5. 模块组（扩充）

### 5.1 定义

模块 = 一组可以开关的附加配置，与具体网站无关。每个模块有：名称、图标、一句话说明、支持的客户端、与其他模块的冲突、在各档位的默认状态。

### 5.2 模块清单

现有 5 个（✅），其余为从社区常见做法中归纳、由我们自己实现的新增项（🆕）：

| 分组 | 模块 | 说明 | 默认 |
| --- | --- | --- | --- |
| 🛡 DNS 与隐私 | ✅ DNS 防泄漏 | 国内域名用国内 DNS，其余跟随分流，避免 DNS 请求泄露真实位置 | 三档都开 |
| | ✅ 阻断加密 DNS | 拦截应用自带的 DoH / DoT，让 DNS 走我们的规则 | 专业 |
| | 🆕 隐私跟踪拦截 | 拦截常见跟踪与遥测域名 | 专业 |
| 🔍 识别准确度 | 🆕 流量嗅探 | 从加密流量中识别域名，提高分流准确度（T1 已默认写入 mihomo） | 进阶起 |
| | ✅ IP 规则补 no-resolve | IP 规则不触发 DNS 解析，更快、更不容易泄露 | 三档都开 |
| | 🆕 禁用 QUIC | 拦截 UDP 443，让部分应用回退到 TCP，提升可分流性 | 专业 |
| 🏠 直连优化 | ✅ 局域网与内网穿透直连 | 局域网、Tailscale / ZeroTier 等直连 | 进阶起 |
| | 🆕 Apple 推送直连 | 保证 iPhone 推送及时 | 进阶起 |
| | 🆕 国内常用应用防误代理 | 微信、支付宝、银行等国内应用强制直连 | 三档都开 |
| | ✅ 游戏下载直连 | Steam 等下载走直连省流量 | 专业 |
| | 🆕 BT / PT 直连 | 下载工具流量直连，避免机场封号 | 专业 |
| ⚙️ 运行 | 🆕 TUN 模式（路由器 / 透明代理） | 为 OpenClash 等写入 TUN 配置；图形客户端用自带开关，默认不写 | 专业 |

社区配置只作为"哪些能力常见"的参考，所有模块内容由我们自己编写，不复制 AGPL 仓库的任何配置。**【待定 D15：模块清单】**

### 5.3 界面

模板详情的"分流"标签旁新增"模块"标签：按分组展示卡片（图标 + 名称 + 一句话 + 开关），不支持当前所选软件的模块显示为灰色并说明原因；冲突的模块不能同时开启（沿用现有冲突检测）。

## 6. 以软件为中心（沿用 r1，已批准）

- **语法族**（内部）：Clash / mihomo 系（含 Stash）、sing-box 系、苹果原生系（含 Egern）。用户只看到软件名、图标、平台。
- **软件目录** `src/shared/apps.ts`（R1 已完成，待合并）：每个软件的平台、语法族、规则订阅链接、完整配置编译器、一键导入、导入后怎么用。Karing、ClashMi 暂为"仅分流规则"，Hiddify 暂不显示。
- **软件图标**：开源软件按许可证取官方图标，闭源软件在你提供图标前用首字母徽章。
- **统一的软件选择器** AppPicker（R1 已完成）：先选平台，再点图标；规则侧单选、模板侧多选。
- **规则侧订阅页**：选软件 → 只给一个最合适的链接 + 图文步骤；全部格式收进"其他格式（高级）"。

## 7. 多条机场订阅（沿用 r1，R3 进行中）

- 最多 10 条，每条可命名；名称作为节点前缀（"机场 1 · 香港 01"）。
- 组合方式：合并所有机场（默认）/ 每个机场一个分组。在三档模型下：简易、进阶默认合并；专业可按机场建节点池。
- 各语法族的处理沿用 r1 §6.4；圈X / Loon 默认不在配置里写远程订阅，完成页引导在软件里添加（D5）。

## 10. 全局动效（扩充 M3.5）

M3.5 已统一按钮、卡片、弹层、列表与基础页面淡入。本版把范围扩展到**整个界面**，仍用同一套时长 token（120 / 200 / 320 ms）与曲线：

| 场景 | 动效 |
| --- | --- |
| 页面切换 | 同级页面（侧栏切换）：淡出 + 淡入（fade-through）；进入详情：内容从右侧轻微滑入，返回时反向（方向感知）；浏览器支持时用 View Transitions API，不支持时退回 CSS 动画 |
| 共享元素 | 列表卡片 → 详情页标题：卡片图标与标题平滑过渡到详情页头部（支持 View Transitions 的浏览器） |
| 标签切换 | 模板详情、设置的标签：下划线指示器滑动，内容区横向淡入 |
| 向导步骤 | 下一步：内容向左滑出、新步骤从右滑入；上一步反向；进度条平滑增长 |
| 加载 | 骨架屏 → 内容交叉淡入；数字（规则数、节点数）计数动画 ≤ 320 ms |
| 列表 | 首次进入的列表项依次出现（每项错开 20–30 ms，最多 8 项）；增删改排序有位移过渡 |
| 主题与语言 | 明暗切换整页颜色交叉淡入；语言切换文字淡入，不闪烁 |
| 侧栏与底栏 | 当前项指示器滑动；手机底栏切换时图标轻微弹性 |
| 反馈 | 复制成功、保存成功：按钮内图标变为勾并回弹；错误：输入框轻微抖动 |

约束（不变）：只动 transform / opacity；无 blur；单个动画 ≤ 320 ms、整页切换 ≤ 400 ms；不阻塞内容渲染，现有"1 万条规则页面切换 < 200 ms"预算不变；`prefers-reduced-motion` 时全部降为瞬时或纯淡入。完成后给你桌面与手机录屏确认。
