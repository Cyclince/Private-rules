# Private Rules 1.1.0 发布说明

> 当前预发布版本：`1.1.0-beta.1`（公开测试版）。正式版 `1.1.0` 将在完成真机客户端验证与公测反馈修复后发布。
>
> 从 1.0.x 升级前，请先阅读 [1.0.x → 1.1.0 升级指南](./upgrade-1.1.0.md)。

---

## 新功能

### 1. 规则模板与多客户端编译（核心新能力）
- **规则目录与内置应用组件库**：统一聚合内置规则目录索引、用户自定义规则集与 GeoSite / GeoIP 数据，提供按应用分类的可复用组件与复制定制（Fork）能力。
- **四档起步模板与修改层**：内置标准起步模板，采用「底稿 + 修改层（Overlay）」模型，支持上游模板变基（Rebase）与版本历史回溯。
- **可视化模板编辑器**（`/admin/templates/:id`）：
  - 拖拽调整组件分层顺序，按需加载编辑器依赖（`dnd-kit`、CodeMirror），不拖累首屏体积；
  - **12 项实时检查器**：自动检测规则遮蔽、组引用缺失、组循环引用、空组、兜底缺失、分层顺序、子集在后、IP 规则缺少 `no-resolve`、正则方言不兼容等问题；
  - **命中测试（Probe）**：输入域名、URL 或 IP 模拟逐条匹配，追踪首个命中规则、所属组件与最终出口；
  - **5 个增强模块**：IP 规则补 `no-resolve`、防 DNS 泄漏、阻断加密 DNS、游戏下载直连、局域网与内网穿透直连，支持冲突检测与实时预览；
  - **模板导入器**：支持从 ACL4SSR `.ini` 与 mihomo YAML 导入生成模板；
  - **输出档位**：支持 `full`（完整配置）与 `minimal`（仅节点、策略组、规则集与规则，适配 OpenClash 等）两档，模板设默认、发布可覆盖。
- **7 个客户端编译器与发布路由**（`/p/:slug/:file`、`/t/:token/:slug/:file`）：
  - **A 类（远程节点引用）**：`mihomo.yaml`（mihomo）、`stash.yaml`（Stash）、`surge.conf`（Surge）；
  - **B 类（服务端解析并内联节点）**：`singbox.json`（sing-box，支持 6 种主流协议的基础解析与加密快照缓存）；
  - **C 类（客户端管理节点，按正则匹配）**：`loon.conf`（Loon）、`qx.conf`（Quantumult X）、`shadowrocket.conf`（Shadowrocket）；
  - 每个发布均生成客户端兼容性报告，明确列出转换、降级或跳过的规则与原因。
- **节点接入与安全快照**：
  - 支持在发布页为节点槽位绑定订阅地址与自定义 `User-Agent`，统一排除公告/流量/到期等非节点条目；
  - B 类客户端（sing-box）支持 30 分钟加密节点快照、并发请求去重与拉取失败自动降级（返回上次成功快照并携带 `X-Node-Snapshot-Stale: true`）；
  - 支持手动拉取节点名预览地区分组与空组校验（仅加密存储节点名，不保存节点凭据）。

### 2. 全新 Miku 设计系统与前端重构
- 全面重建管理后台（`src/web/`），统一 Miku 青色主题与深浅双色 Token（全部前景/背景组合通过 WCAG AA ≥ 4.5:1 对比度校验），修复首屏主题闪烁。
- 桌面固定侧栏、平板可折叠抽屉、手机 4-Tab 底部导航三视口响应式布局，页面筛选与选中状态持久化至 URL。
- 基于 TanStack Router + TanStack Query + Hono RPC 重构数据层，消除 1.0.x 重复请求；支持 1 万条规则服务端搜索与游标分页。
- 构建期生成繁体中文（`zh-TW`），彻底移除约 1.09MB 运行时 `opencc-js` 分包，首屏 JS 严格控制在 120KB（gzip）以内。
- 更新 PWA 清单与 Service Worker（`v4`），严格禁止缓存 `/api`、`/rules`、`/sub`、`/p`、`/t`、`/health` 等敏感或动态接口。

### 3. 规则引擎与后端架构升级
- 规则同步新增**覆盖关系去重**与**按行为拆分输出**能力；保留 14 种规则类型（含 `SRC-PORT`），IPv6 统一入库为 `IP-CIDR`（输入兼容 `IP-CIDR6` 别名），`no-resolve` 独立持久化。
- 采用 Drizzle ORM 统一表结构单一来源，重构迁移系统（`src/data/migrations/`），支持 D1 与 SQLite 双数据库契约一致运行与幂等升级。
- 规则集与模板发布订阅均支持 **ETag / 304** 与 5 分钟缓存（Cloudflare 使用 Cache API），任一关联数据变更自动失效。
- 备份格式升级为 **版本 2**（支持模板、组件与发布结构，不含节点订阅地址），同时完全兼容无损导入 1.0.x 的版本 1 备份。

## 修复与改进

- **1.0.x 遗留数据无损升级**：自动识别 1.0.x 的 `d1_migrations` 与运行时建表两种历史状态，自动补齐缺失表/列并容忍列顺序差异；Docker/SQLite 形态升级前自动生成 WAL 安全的 `.bak-1.0.x` 备份；升级后 1.0.x 规则集订阅输出与 1.0.7 黄金基准逐字节一致（`PROCESS-NAME` 例外见下文「行为变化」第 6 条）。
- **统一安全与错误处理**：所有 API 输入经 Zod 严格校验，错误响应统一为扁平结构 `{ ok: false, error, code, details? }`，前端按 `code` 本地化提示且不泄露内部堆栈；远程拉取统一强化 SSRF 防护（拦截内网与保留网段、禁止重定向、15s 超时、20MB 大小上限）。
- **配置注入防护**：编译输出前对策略组名、节点名与备注进行转义，防止恶意节点名称注入规则。
- **CI 质量与内核验证**：CI 新增固定版本（SHA-256 校验）`mihomo -t` 与 `sing-box check` 编译产物核验、三视口 Playwright E2E、最新 Node 兼容检查、生产依赖漏洞扫描（高危及以上阻断）与前端体积门禁。

## 破坏性变化

### 1. Telegram Mini App 会话权限收紧
- 服务端对 Telegram Mini App 会话强制执行最小权限边界，直接拦截以下高风险操作并返回 `403 FORBIDDEN`（同步写入审计日志）：
  - 备份导出、校验与导入（`/api/backup*`）；
  - API Key 查询与管理（`/api/api-keys*`）；
  - 基础设施类设置修改（`baseUrl`、`githubMirrorUrl`、`publicLinksEnabled`、`tokenLinksEnabled`、`customIconPackUrls`、`customIconPackNames` 等）。
- Telegram 会话仍可正常进行规则集与来源管理，以及策略名称/图标自动更新偏好调整；上述高风险操作请使用浏览器管理员会话完成。
- **Telegram Mini App 会话滑动续期**：单次有效期仍为 30 分钟，请求校验通过且剩余有效期不足一半时自动续期 30 分钟（累计绝对上限 7 天，并同步刷新 Cookie），避免停留在面板超过 30 分钟后因 `initData` 不可重放而退回密码页。

### 2. `/api/*` CORS 与 CSRF 策略收紧
- **`/api/*` 不再返回 `Access-Control-Allow-Origin: *`**，仅允许同源浏览器访问；公开订阅路由（`/rules/*`、`/sub/*`、`/p/*`、`/t/*`）继续保留 `Access-Control-Allow-Origin: *`。
- **Cookie 会话写操作强制 CSRF 校验**：`POST` / `PUT` / `PATCH` / `DELETE` 请求必须携带 `Content-Type: application/json` 且 `Origin` 与 `BASE_URL` 或当前请求 Host 同源，否则返回 `403 CSRF_REJECTED`。使用 `Authorization: Bearer prk_...` 的 API Key 自动化脚本豁免 `Origin` 校验。

### 3. 节点绑定强制要求显式配置 `SESSION_SECRET`
- 节点订阅地址使用基于 `SESSION_SECRET` 派生的 AES-256-GCM 密钥加密存储，**不再回退使用数据库内自动生成的密钥**。
- 未通过环境变量显式配置 `SESSION_SECRET` 时，应用仍可启动并照常使用规则集功能，但绑定/读取节点订阅会返回 `503 SESSION_SECRET_REQUIRED`。
- Node/Docker 生产环境（`NODE_ENV=production`）下，显式配置的 `SESSION_SECRET` 长度必须不少于 **32 个字符**。
- 凡包含任意节点绑定的发布，访问策略强制限制为 `token` 或 `disabled`，禁止设为 `public`（尝试切换或绑定返回 `400 VALIDATION_FAILED`，`/p/:slug/:file` 也会二次拦截并返回 `404`）。

### 4. 前端旧版界面移除
- 1.1.0 直接以新版 Miku 前端接管 `/admin` 与 `/pwa-install`，不再提供旧版界面回切入口。
- 1.0.x 书签深度链接（如 `/admin?view=rules&category=:id`、`?view=sources`、`?view=links`、`?view=settings`）及开发过渡路径 `/preview/*` 均自动重定向至对应新版页面；1.0.x 后端兼容路由（`/api/categories`、`/api/data` 等）继续保留。

### 5. 备份格式升级为版本 2
- 导出备份默认输出 `version: 2`（包含规则集、设置、自定义组件、模板与发布元数据，不含节点订阅地址与加密快照）。
- 1.1.0 兼容导入 1.0.x 的 `version: 1` 备份，且仅覆盖规则集与设置，不会清空 1.1.0 中已创建的模板与自定义组件；但 `version: 2` 备份无法直接导入回 1.0.x。

### 6. `PROCESS-NAME` 规则的输出调整（逐字节一致的唯一例外）
- 仅影响含 `PROCESS-NAME`（按进程名分流）规则的规则集，其余规则集升级后输出与 1.0.7 逐字节一致。
- **Loon（`-loon.list`）与 Quantumult X（`-qx.list`）**：iOS 客户端无法按进程分流，1.0.7 照常输出的 `PROCESS-NAME` 行在 1.1.0 中直接省略（不留注释）；该规则仍会在后台兼容性报告中列为已跳过。分流效果与之前相同。
- **sing-box（`-sing-box.json`）与通用 JSON（`.json`）**：1.0.7 会丢弃 `PROCESS-NAME`，1.1.0 正确输出为 `process_name`，桌面端 sing-box 上这些规则将开始生效。
- Surge、Clash Classical、Shadowrocket、通用 `.list` 等格式不受影响。

## 已知限制与待验证项

1. **Quantumult X 与 Loon 完整配置为实验性功能（未经真机验证）**：
   - 默认情况下，Loon 与 Quantumult X 发布仅输出「仅规则资源」模式（Loon 远程规则 / QX `filter_remote`），避免直接导入完整配置时覆盖客户端中已有的节点订阅；
   - 如需输出完整配置，需在发布编辑页手动开启「实验性完整配置」开关（兼容性报告会明确提示 `EXPERIMENTAL_FULL_CONFIG_UNVERIFIED`），务必先备份客户端现有配置并在独立测试槽中验证。
2. **`sing-box` 最低支持官方版本为 1.12**：
   - sing-box 编译器按官方 1.12 的 `route.rule_set` 与新版 DNS / action 语法输出，CI 已固定 `sing-box v1.12.25` 执行 `sing-box check` 校验；不再兼容 1.11 及更早版本的旧版配置语法。
3. **sing-box 服务端节点协议覆盖范围**：
   - B 类解析器当前覆盖 Base64 分享链接与 Clash YAML（`proxies:`）中的 6 种协议：Shadowsocks、VMess、VLESS（含 Reality）、Trojan、Hysteria2、TUIC。其他协议会被安全跳过并在兼容性报告中注明。
4. **真机客户端实测尚未全部签收**：
   - 各客户端编译输出已通过快照测试（mihomo 与 sing-box 已通过 CI 内核语法检查），7 个客户端的真机导入与分流验证清单见 [真机验证清单](./device-test-checklist.md)，欢迎在公测阶段协助验证反馈。
5. **视觉素材与后续规划**：
   - 登录页背景、仪表盘顶部横幅、空状态插画、关于徽章与 PWA 图标等 Miku 视觉素材均已定稿并接入；
   - MRS 二进制规则集产物与 subconverter `.ini` 导出规划在 `1.2.0` 提供。
